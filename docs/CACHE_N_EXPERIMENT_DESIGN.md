# CACHE_N 加宽实验设计（中端 · Watch）

状态: **请 WorkBuddy 补全并盯盘**  
日期: 2026-07-23  
前提: P0 显示 77.7% 大涨票在 ML Top500 外；规则层已接受为上限，本实验只做**有限探测**。

---

## 目标

在不扫全 A、不用万得全市场的前提下，测：把评分缓存从 **500 → 800 / 1000**，能否多救一点「可交易 ≥5%」票，同时 Top2 胜率/回撤不崩。

---

## 假设

| ID | 假设 |
|----|------|
| H1 | Top501–800 里仍有少量次日 ≥5% 且可买的票 |
| H2 | 这些票经 SURGE_ARM_B 软门后，进入展示池的比例上升 |
| H3 | 下单 Top1–2 的胜率与 maxDD **不明显变差**（否则停） |

---

## 实验组（建议）

| 组 | CACHE_N | 其他 |
|----|---------|------|
| Ctrl | 500 | `ENABLE_SURGE_ARM_B=1`（生产） |
| E1 | 800 | 同上 |
| E2 | 1000 | 同上 |

改动点：`recommend.py` 中 `CACHE_N`（或 env `RECOMMEND_CACHE_N`）。  
**不要**同时开旁路大幅加宽（一次一变量）。

---

## 样本与指标（WorkBuddy 填具体区间）

- 样本外交易日：**15 个交易日（2026-07-24 ~ 2026-08-13，含）**
- 对比方式：同期回放 P0 kline 数据，Ctrl(CACHE_N=500) vs E1(800) vs E2(1000)，用 15 日真实涨幅验证
- 主指标：
  - 可交易 hit≥5%（T+1 开买得到）
  - Top2 胜率 / 笔均 / maxDD
  - 额外进入缓存且最终进池的 ≥5% 只数（相对 Ctrl）
- 停损线（建议）：
  - Top2 胜率较 Ctrl 下降 >3pt，或 maxDD 明显恶化 → **停，承认上限**
