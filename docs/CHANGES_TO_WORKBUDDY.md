## 二、2026-08-02 改动清单

### 2.1 封成比（封单成交比）实证研究

**目的**：验证"封成比五档 → 次日溢价"策略的有效性，并校准阈值。

**数据**：2026-04-01 ~ 2026-07-31（4 个月），同花顺涨停池 6,374 条涨停 → 有效 5,835 条（含次日行情）。

**核心结论**：
- 五档方向正确，单调性显著：封成比>10 → 次日开盘+11.1%、连板率 85.7%；封成比<0.5 → 次日开盘+1.5%、连板率 15.4%。
- **封成比必须分板型**：一字板封成比>3 → 次日+10.9%（连板率 88.6%）；换手板封成比>1 → 仅+2.9%。90% 换手板封成比<0.5，统一阈值会误判。
- **换手率是最大干扰因子**：低换手(<5%)+封成比>1 → 次日+7.4%、连板率 58%（最优组合）；高换手(>20%)即使封成比高次日也是负溢价。

**本地改动**（不影响服务器生产文件）：
- 新增 `research/fengchengbi/` 目录：抓取/分析脚本 + 数据 + `REPORT.md`。
- **`qmt_model_plan_c.py`**（本地，供用户粘贴到 QMT 编辑器，非服务器文件）：把原 `bid1_vol/volume>=3` 的粗判升级为 `_seal_ratio_decision()` 分层决策表（14:45 后计算封成比 → HOLD/SELL/NEUTRAL）。

**待确认**：WorkBuddy 的 `trade_executor.py`（471 行，Plan C）是否也想加入封成比延期逻辑？如需统一，可基于本研究的阈值做服务端同步。

### 2.2 非涨停强势股验证（已完成）

**问题**：无涨停、但"封成比/换手率达标"的股票，次日表现如何。

**方法**：用服务器 `kline_all.parquet`（4991 只，2025-01~2026-07-31）筛选当日涨幅 5%~涨停线以下的非涨停股，按换手率分层看次日溢价。
**脚本**：`/tmp/analyze_nonlimit_tmp.py`（临时，不落生产目录），结果已下载到本地 `research/fengchengbi/nonlimit_report.txt`。

**核心结果**（69,052 样本）：
- 总体：次日开盘 **-0.38%**、收盘 -0.06%，开盘胜率仅 34.8%（次日 65% 概率低开）
- 换手率分层：换手<3% → +0.01%；换手3~5% → -0.10%；换手5~10% → -0.24%；换手10~20% → -0.60%；**换手>20% → -1.34%**（最差）
- 次日涨停率整体仅 2.6%

**结论**：**封成比体系不能泛化到非涨停股**。没有涨停就没有封单，封成比概念不成立；单纯"当日大涨+高换手"的非涨停股次日大概率低开/平开，无买入价值。换手率在非涨停场景是**反向**指标。封成比的价值仅在 QMT 持仓端（已涨停持仓的隔夜/出货决策）。

### 2.3 非涨停股"共通因子"探索（已完成）

**问题**：非涨停股没有封成比。用户要求找一个类似因子，并看次日**盘中最高点**（假设 +3%/+5% 止盈），而非次日开盘。

**发现 1：CLV 收盘位置值验证失败**。CLV=(close-low)/(high-low) 模拟"买盘控制强度"，结果**方向相反**——收盘越贴最高，次日越弱（换手<5% 时 CLV≥0.9 档 3%止盈实收仅 +0.16%，CLV<0.5 档 +0.48%）。原因：非涨停股没有封单锁筹，冲高的获利盘次日直接兑现。

**发现 2：真正的共通因子 = 换手率（缩量程度）**，单调有效（69,052 样本）：

| 换手率 | 次日开盘 | 次日最高 | 触及+3% | 3%止盈实收 |
|---|---|---|---|---|
| <1%（极缩量） | +0.85% | +2.75% | 43.8% | **+0.93%** |
| 1~2% | -0.02% | +2.54% | 33.7% | +0.25% |
| 3~5% | -0.10% | +3.04% | 38.7% | +0.14% |
| 5~10% | -0.24% | +3.27% | 41.2% | **-0.03%** |
| >20% | **-1.34%** | +3.94% | 47.2% | **-0.81%** |

**结论**：换手<1% + 当日涨5%+ 等价于涨停股"封成比>1"的锁筹形态（唯一正溢价档），但次日最高仅 +2.75%、+3% 止盈实收仅 +0.93%，**远达不到涨停股 +5~10% 的量级**，样本也仅 764 个（1%）。非涨停强势股整体无次日交易价值。

**脚本**：`research/fengchengbi/analyze_nextday_upside.py`（服务器 `/tmp` 运行），结果在 `research/fengchengbi/nextday_upside_report.txt`。

## 三、2026-08-03 改动：QMT 实盘止盈改为「跟踪止盈」

### 背景

用户澄清 T+1 止盈真实逻辑：
1. **触发条件**：明天盘中触及 **+3%** → 触发卖出条件
2. **后续操作**：继续上涨 → 继续持有等待
3. **回撤触发**：一旦从峰值回撤到一定阶段 → 开始卖

即：**跟踪止盈（trailing take-profit）**，3% 是"激活线"不是"卖出线"。

### 改动内容（本地 `qmt_model_plan_c.py`，用户粘贴到 QMT，非服务器文件）

删除原固定档位止盈（`+5%减半 / +10%全卖`），改为与 `trade_executor.py` 一致的跟踪止盈：

| 参数 | 值 | 含义 |
|---|---|---|
| `TP_ARM_PCT` | 3.0 | 收益 ≥3% 激活跟踪（不卖，记录峰值） |
| `PEEL_PULLBACK_PCT` | 1.5 | 从峰值回撤 1.5% → 减半 |
| `PEEL_MAX_STEPS` | 2 | 前两次减半，第三次清仓（共 3 刀） |

关键行为（与 `trade_executor.py` 的 `TRAIL_ARM=3% + PEEL_PULLBACK=1.5% + PEEL_MAX_STEPS=2` 一致）：
- 减半后须**再创新高**才允许下一刀（防回撤途中连续割）
- 浮盈消失（<0%）→ 退出跟踪模式，回到 -3% 分级止损 / -5% 硬止损框架
- 剩余不足 2 手 → 直接清仓（A股最小 100 股）

**同时修复一个 bug**：`sync_holdings` 原把已有持仓 `buy_date` 设为当天，导致 T+1 保护误判（重启模型后所有持仓被当作"今天买的"而无法卖出）。已改为 `buy_date=""`（未知买入日 → 不触发 T+1 冻结，可正常止盈止损）。

### 与 OOS 标签的一致性

用户确认止盈触发 = **盘中触及 +3%**（非收盘站上 +3%）。本地 walk-forward OOS 标签已改为 `high[明日]/close[今日]-1 > 3%`，最终结果 `v25_oos_walkforward_local_fd1.json`（AUC 均值 0.7136）。

### 待确认

- QMT 实盘与服务器 `trade_executor.py` 的止盈逻辑现已一致（3% 激活 + 回撤 1.5%）。**是否需要把 `paper_trading_signals.py` 的 `exit_policy` 也从固定档位同步为跟踪止盈描述？**（目前其 `ladder_tp` 仍写 `[[0.05, 0.5], [0.10, 1.0]]`，与实际跟踪止盈不符）

### 9.5 AUC 安全门（2026-08-08 追加，含 9.6 噪声修正）

> 触发: 钱多爸「如果发现新模型的 AUC 低于旧模型，那当然不能替换了。自我学习提升的意义就是：有提升才替换」
> 修正触发: 钱多爸「小样本训练和全样本训练相比，会不会有 AUC 的差别？这有时会导致 AUC 不准确，从而错过真正的、更好的 AUC」

#### 9.5.1 第一版（严格模式，已被 9.6 取代）

- **规则**：新模型 `v25_opt_auc` 必须 ≥ 旧模型才替换；新 AUC 缺失→保守拒绝；旧缺失（首次部署）→直接采用
- 端到端实测：300 只小训练 0.7220 < 旧 0.7227 → 正确拒绝

#### 9.5.2 实证发现的问题（钱多爸质疑后验证）

| 训练样本量 | AUC | 若用于生产门判定 |
|---|---|---|
| 300 只 | 0.7220 | 误拒（-0.0007，看似接近全样本） |
| 1000 只 | 0.7184 | 误拒（-0.0043） |
| **全样本 5002 只** | **0.7227** | 生产基准（唯一有效口径） |

→ **小样本 AUC 有偏差且方向不定**（300 只反而比 1000 只高）。若用 `--max-stocks` 的 AUC 做生产替换判定会系统性误拒。且历史全样本相邻两日 AUC 波动可达 ±0.005（8-05: 0.7175 → 8-06: 0.7220），验证集 AUC 本身有噪声。

#### 9.5.3 最终设计（容忍区间 + 测试隔离）

1. **生产永远全样本**：`--max-stocks` 仅用于 smoke 测试 → **test 模式**（不备份/不替换/不写生产，仅报告 AUC 结论，`status.mode="test"`）
2. **AUC 容忍区间**：`新 AUC ≥ 旧 AUC - --auc-tolerance`（默认 **0.003**）→ 替换。因为验证集 AUC 有噪声（±0.005），且**新模型用了更新鲜的数据，数据新鲜本身是价值**；只有下降超容忍（明显退化）才拒绝替换
3. 边界浮点：`diff < -tolerance - 1e-9` 防边界抖动

#### 9.5.4 实测（新版）

- `--max-stocks 300` → `[TEST] new_auc=0.7220 vs 生产 0.7227 → 门通过（-0.0007 在容忍内）；smoke 模式不替换`，`swapped: []`，生产 mtime 未动 ✅
- 旧逻辑下 300/1000 只会误拒；新逻辑下只有**全样本真实退化**（如 8-05 的 0.7175 出现在新模型）才会拦

**现在的完整保护链**：训练失败回滚 → 容忍区间内替换/超容忍拒绝（仅全样本口径）→ 40 交易日 OOS 验收（不足标 INSUFFICIENT）→ 结构性换模需人工审核（`auto_install_forbidden`）
