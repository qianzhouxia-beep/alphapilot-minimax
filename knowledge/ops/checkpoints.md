> 细节仍在各自知识卡 / CHANGELOG 里；本表只记时间点、分层、任务，避免把 IC、选股、买卖混在一起。

可视化扫一眼（旁路快照，以本文件为准）：打开 Cursor 里的 checkpoint canvas。

## 怎么记（流程）

1. 先判定这一层是 **选股模型** / **买卖模型** / **数据** / **文档**，不要写「策略」。
2. 做完一件可复查的事（部署、定调、接线、否决），在下面表格**最上面**加一行。
3. 还没做完、容易忘的，放进 **待盯**；做完后改状态，不要删行。
4. 同类易混事项必须在「不要和…混」列写清楚。
5. 细节链接写到知识卡或 `production_strategies/CHANGELOG.md`，本表不写长文。

| 列 | 含义 |
|---|---|
| 日期 | `YYYY-MM-DD`，必要时加时刻 |
| 层 | 选股模型 / 买卖模型 / 数据 / 文档 |
| 任务 | 一句话：做了什么 |
| 状态 | `待盯` / `已完成` / `未做` / `否决` |
| 下次看 | 什么时候、看哪个文件或数字 |
| 不要和…混 | 最容易搞错的那件事 |
| 详情 | 知识卡或 CHANGELOG 锚点 |

Agent 规则：`.cursor/rules/checkpoints.mdc`（每次实质性改动必须回写本表）。
