# 晋升门改造（ADR 草案 · 待老板/ WB 评审）

## 0. 老板提出的问题（2026-09-13）

> 「OOS 又要 40 天，小于 40 天不能部署 —— 这永远是个死循环：周末训出来要等 40 天，
> 40 天后环境又变了又该重训，又要等 40 天。这个方案可能有缺陷。」

**结论：老板判断正确，现行门确实有结构性缺陷。** 本 ADR 给出替代方案。

## 1. 现行门缺陷：40 天是「唯一真相闸」，且与重训耦合

现行两个脚本都用 `MIN_DAYS = 40`（训练截止日之后**真实**交易日）：

| 位置 | 逻辑 |
|---|---|
| `rd_workshop/run_promotion_adapter.py` | `n_days >= 40` 才判 PASS，否则 `INSUFFICIENT_OOS` |
| `scripts/run_oos_tradable_top2.py` | 同上 |

缺陷三条：

1. **死循环**：候选每次重训 ⇒ OOS 计数归零 ⇒ 再等 40 天（实测 09-12 候选 `OOS days=0`）。
2. **「40」无依据**：没有噪声带支撑，纯粹拍脑袋的固定天数。
3. **单点判定**：只有「真跑够天数」一条路，重训/环境变化不会缩短等待。

## 2. 关键事实：生产其实没有「冻结等 40 天」

现行**生产**重训（`scripts/run_daily_retrain.py`，21:30 cron）用的是**验证集 AUC 容忍门**：

```
新 AUC >= 旧 AUC - 0.003  →  原子替换（数据新鲜本身是价值）
新 AUC <  旧 AUC - 0.003  →  拒绝替换
失败/超时 → 从 retrain_backup 自动回滚
```

即**生产本来就在「快验证 + 自动回滚」**，而且 09-11 因 `0.7162 vs 0.7221(−0.0059)` 被正确拒绝过。
**RD 候选的 40 天门与生产实际门不一致** —— 这才是最该修的地方。

## 3. 替代方案：四件套

### 3.1 历史 walk-forward（已落地 `rd_workshop/walkforward_oos.py`）

把「等 40 个未来交易日」压缩成「一次跑完过去 N 个月的多折」：

- 每折在**同一批测试样本**上配对评估两臂：候选（只用该折测试窗之前的数据现场训练）vs 生产（读冻结 `.ubj`）；
- 输出逐折 AUC / RankIC / Top5 / Top10 超额，以及**配对差**与**折间标准误** ⇒ **数据驱动噪声带**（`noise_band_95 = 1.96 × SE`）；
- 判据从「天数够不够」变成「配对差是否 `beyond_noise`」。

**边界**：只读 `models/`+`data/`，只写 `rd_workshop/walkforward_runs/`，不自动晋升。

### 3.2 生产同口径 canary（**这是你选的「放"真候选"进生产带自动回滚」**）

历史 walk-forward 只证明「历史上更好」，不证明「今天部署不掉线」。所以再加一层**短跑**：

- 候选与生产**同口径并行跑 K 个交易日**（建议 K=5~10，而非 40）；
- 逐日配对超额，一旦触发回滚线立即自动回退；
- 通过 ⇒ 落地；不通过 ⇒ 回滚并记录。

K 从 40 压到 5~10 的依据：canary 只负责抓「部署后才暴露的问题」（数据管道、特征错位、分布漂移），不负责抓 alpha —— alpha 交给 3.1。

### 3.3 自动回滚闸（复用生产已有机制，不新造）

沿用 `run_daily_retrain.py` 的成熟模式：备份 → 原子替换 → 状态落盘 → 失败/退化自动 `restore_backup`。
canary 期的回滚线建议：**连续 2 日超额 ≤ −X，或任一日 ≤ −2X**（X 取 3.1 的噪声带）。

### 3.4 评审节奏：把「重训」与「评估」解耦

死循环的根因是两者耦合。解耦后：

- 重训可**随时**发生（数据新鲜是好事）；
- 评估用**滑动窗口**持续累计（历史 walk-forward + 生产 canary），不因重训归零；
- 候选在「正式评估窗」里稳定 ≥N 折后再谈晋升。

## 4. 门的新旧对照

| 维度 | 现行 | 提议 |
|---|---|---|
| 主判据 | 真实日数 ≥ 40 | 配对差 `beyond_noise`（历史多折） |
| 部署前额外验证 | 无 | 生产同口径 canary 5~10 日 |
| 失败处置 | 等够天才评估 | 自动回滚（已有备份/原子替换/回滚） |
| 重训后 | OOS 归零，重等 40 天 | 评估窗滑动累计，**不归零** |
| 与生产门一致 | 否（40 天 vs −0.003） | 是（同一套噪声带/回滚语义） |

## 5. 风险与诚实边界

1. **历史 walk-forward ≠ 未来**：它防的是「过拟合历史」，防不了 regime 突变 ⇒ 这正是保留 canary 的理由。
2. **折数少 = 噪声带粗**：折间 SE 估计对折数敏感；建议 ≥6 折，折数少时明确标注「噪声带不可靠」。
3. **候选臂结构性偏弱**：现场重训通常只在有限切片上（`train_tail`），而生产是全市场冻结模型 ⇒ **该对比中的负 Δ 不等于「重训更差」**，需在文档里写清，避免误读（本次 smoke 已出现此现象）。
4. **不自动晋升**：ADR-0001 边界不变，任何晋升仍需人工。
