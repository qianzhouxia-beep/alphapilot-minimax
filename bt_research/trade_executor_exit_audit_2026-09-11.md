## 2. 真实问题（服务器版，均已核实）

### A. `exit_policy` 元数据陈旧（中）
- `trade_executor.py:505-513` 写入 `exit_policy.ladder_tp = "[[0.05, 0.5], [0.10, 1.0]] ..."`，但 `LADDER_TP` 常量注释明写 **"(已废除, 改用趋势跟踪峰值回撤6%)"**。
- 后果：任何读 `paper_trading.json[:exit_policy]` 的人/程序（含 WB 本轮、`api_server.py:780+`）都会得到**已废除的规则**。
- 附加：`api_server.py:858-860` 从 `exit_policy` 取 `trail_arm` / `peel_pullback` / `hard_stop_pct`，而这三个 key **在 trade_executor 写入的 exit_policy 里不存在** ⇒ 静默回落默认值 `0.03 / 0.015 / -0.10`。
- **建议**：`exit_policy` 改为写入**实际生效**字段（`hard_stop_pct=-0.05`、`ladder_stop=[[-0.03,0.5]]`、`trail_exit_pct=0.06`、`max_hold_days=15`、`ladder_tp: abolished`），并补齐 api_server 读取的 key。

### B. `CONSECUTIVE_MIN=3` 语义与排程不符（中）
- 注释 = "−3% 需连续 **3 分钟**"；实现是每次执行 `consec_low += 1`。
- 但 `trade_executor` cron 为 **每 10 分钟**（09:42/52、10:02/12…、14:02…22）⇒ 实际需 **≈30 分钟**连续低于 −3% 才减半。
- 后果：**分级止损远比设计迟钝**，弱市少一道保护。
- **建议**：二选一——把 `CONSECUTIVE_MIN` 改为 1（10 分钟内已确认破位即减半），或把该分支改为按分钟级排程/盘中独立轮询；并把注释与常量对齐。

### C. 涨停判定未区分板块（低）
- `is_limit_up = pnl_pct >= 9.5 and (bid1/vol)>=3`，对**双创（20% 涨停）**同样阈值。
- 后果：双创股 +9.5% 未真封板时被当"涨停封板"持有，**跳过趋势止盈 6%**。
- **建议**：按板块取阈值（主板 9.5 / 双创 19.5），或复用已有的 `_limit = 21.0 if 30/68 else 11.0` 同类判定。

### D. 死变量（低，清理即可）
`use_tp`(149)、`t1_force_min`(133)、`is_t1_window`(134, 仅日志)、`import urllib.request as _req`(141)、`LADDER_TP`(26) 均已无实际作用。
